# ADR-0004: CLI with Typer

**Date:** 2025-08-17
**Status:** Accepted

## Context

A productive CLI is needed for world-building and testing, emphasizing strong help UX.

## Decisions

- **Framework:** Use Typer for a multi-command CLI.
- **Commands:** Mirror client API (e.g., `new`, `load`, `tick`) with `--format table|json`. Commands are thin wrappers over pure functions.
- **CLI Features:**
  - Expose user flows without engine internals.
  - Delegate to client API, ensuring predictable output and exit codes.

### Command Topology

- **Root Command:** `saskan`
- **PR-2 Scope:**
  - `saskan connect` — handshake probe
  - `saskan start` - fire up the server
  - `saskan version` — prints versions for sanity checks
- **Future Namespaces:** Reserve `game`, `dev`, `admin`.

### Config Precedence

- **Order:** CLI flags > environment > defaults.
- **Keys for PR-2:** `host`, `port`, `protocol`.
- **Environment Variables:** `SASKAN_HOST`, `SASKAN_PORT`, `SASKAN_PROTOCOL`.

### I/O Discipline

- **stdout:** User-facing success messages.
- **stderr:** Errors (e.g., reject, timeout).
- **Logs:** Server-side only, not in CLI output.

### Exit Codes

- `0`: Success
- `10`: Reject (protocol/version issues)
- `11`: Timeout/network error
- `12`: Invalid arguments/config

### Layering

- **Structure:** `ui_cli` interacts only with the client API.
- **No Direct Engine/Core Imports:** Keep CLI modules separate.

### Help & UX

- **Help:** Concise with defaults shown.
- **Out of Scope for PR-2:** Dry-run flag to avoid feature creep.

## Consequences

- Consistent ergonomics and autogenerated help.
- Easy testing with a minor learning curve due to Typer dependency.

## Alternatives Considered

- **argparse:** More boilerplate.
- **Click:** Similar but Typer aligns better with type hints.

## Notes/Follow-ups

- Establish examples in help text.
- Add Typer test helpers later.
